# ems-agent 边界处方

> 本文档记录项目中遇到的边界情况及其处理方案

| 场景 | 处方 |
|---|---|
| 不在 git 仓 | 建议 `git init`;拒则跳阶段 4 commit 建议 |
| 已存在 CLAUDE.md | AskUserQuestion:覆盖 / 合并 / 取消;合并保留用户段只补缺失 |
| 已存在 `llm-ai/` | 走 D.2 流程 |
| 无依赖描述文件 | 跳依赖侦察,标"未发现",用户确认 |
| 文件 >5000 monorepo | 侦察采样前 3 workspace,告知需显式指定子包 |
| 多语言混合 | 仅主语言体检,其他列树标"未纳入" |
| 体检发现线上漏洞 | 独立开 `error-security-*.md`,建议立即处理 |
| 中途改模式 | 回 0.2 重选,已生成文件去留问用户 |
| 规则冲突 | 停下描述冲突,用户拍板 |
| mock 计划移除 | 元信息标"计划移除",新代码不依赖,不写入作为约定 |
| 历史素材文件 | 保留不删,踩坑索引 grep 关键词加"历史素材引用"条目 |
| 复审虚假断言 | grep 复核未命中 → 驳回,记"复审误判" |
| git 历史泄密 | 未与生产重合=中等(迁 `.env.local`);重合=严重(`git filter-repo` + 改密) |
| 协议文档字段缺 | 标 `TODO: 协议文档未明确`,登记 §7,禁推断 |
| 协议点表 csv/xlsx | 标"用户提供未直接解析",要求用户填首段 |
| 多样式并存 | 记两条主流 + 比例 + 适用场景,不强行二选一 |
| 改动违样式但合理 | 提示"是否同步更新 `代码样式.md`?",用户裁决 |

## 项目特定边界

### .env 文件处理
- **场景**: 根目录存在 .env 文件（4311 字节），.gitignore 已包含 `.env` 规则
- **处方**: 
  1. 确认 .env 是否包含生产凭据
  2. 如包含生产凭据且已提交到 git 历史，执行 git 历史泄密处方
  3. 如仅包含开发凭据，确保 .gitignore 生效

### 内网 IP 入仓
- **场景**: .env.example 中硬编码 `EMS_BASE_URL=http://192.168.1.100:8080`
- **处方**: 
  1. 确认是否为示例 IP 还是真实生产 IP
  2. 如为真实 IP，评估是否需要脱敏
  3. 建议使用占位符（如 `http://your-ems-server:8080`）

### Node 版本未声明
- **场景**: package.json 缺少 engines 字段
- **处方**: 
  1. 根据依赖（tsx、TypeScript 6.0.2、better-sqlite3）推断最低 Node 版本
  2. 建议添加 `"engines": { "node": ">=18.0.0" }`

### README 空白
- **场景**: README.md 为空文件（0 字节）
- **处方**: 
  1. 生成基本项目说明（技术栈、启动方式、环境变量配置）
  2. 参考 KNOWLEDGE.md 和 .env.example 补充内容

### 文件数量不符
- **场景**: 用户声称 <20 文件，实际约 30 个 TS 文件
- **处方**: 
  1. 以实际文件数为准
  2. 生成代码索引.md（≥20 文件触发条件）
