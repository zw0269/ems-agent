# ems-agent 代码索引

> **最后更新**: 2026-05-02

## Quick Facts

- **技术栈**: Node.js + TypeScript (ESM模块)
- **入口**: src/index.ts
- **构建**: `npm run build` (tsc)
- **启动**: `npm start` (tsx src/index.ts)
- **开发**: `npm run dev` (tsx watch src/index.ts)
- **测试**: `npm test` (vitest run)
- **Lint**: 无配置
- **本地启动完整性**: 需要 .env 文件（LLM_PROVIDER、LLM_API_KEY、EMS_BASE_URL 等）+ EMS Java 后端可达

## §3 调用关系

### §3.1 入口 → 核心流程

```
src/index.ts (main)
  ├─> getDb()                          # 初始化数据库
  ├─> recoverStaleProcessingAlarms()   # R2 崩溃恢复
  ├─> checkLLMConnectivity()           # 健康检查
  ├─> Heartbeat.start()                # 启动心跳轮询
  │     └─> AlarmQueue.push()          # 告警入队
  ├─> startStatusServer()              # 启动状态面板
  ├─> aggregateAcceptedSuggestions()   # 聚合 AI 改进建议
  ├─> setInterval (P3 快速通道)
  │     └─> processAlarm()
  └─> setInterval (主消费循环)
        └─> processAlarm()
              ├─> gatherSnapshot()     # 并行采集实时数据
              ├─> gatherHistory()      # 采集历史告警
              ├─> checkThresholds()    # 阈值检查
              ├─> AgentLoop.run()      # AI 推理
              └─> notifyOperator()     # 发送通知
```

### §3.2 AgentLoop 推理流程

```
AgentLoop.run() / runOnce()
  ├─> buildSystemPrompt()              # 构建系统提示词（含 KNOWLEDGE.md + self-improvement.md）
  ├─> buildUserMessage()               # 构建用户消息（告警 + 实时数据 + 历史）
  ├─> LLMClient.call()                 # 调用 LLM API
  │     ├─> Anthropic SDK / OpenAI SDK
  │     └─> insertLLMCall()            # 记录 API 调用（审计追踪）
  ├─> ToolRouter.execute()             # 执行工具调用
  │     └─> queryEms.ts 函数           # 查询 EMS 后端
  ├─> buildSelfReflectionPrompt()      # 自我反思（软件故障）
  └─> insertSelfImprovement()          # 保存改进建议
```

### §3.3 跨模块共享状态

- **statusStore** (server/statusStore.ts): 全局内存状态，被 index.ts、statusServer.ts 读写
- **SessionManager** (gateway/sessionManager.ts): 会话锁，防止同一告警重复处理
- **AlarmQueue** (gateway/alarmQueue.ts): 告警队列，被 Heartbeat、statusServer、index.ts 操作
- **数据库单例** (db/database.ts): getDb() 返回全局 SQLite 连接

## §5 数据流

### 典型告警处理链路（软件故障）

```
1. EMS Java 后端产生告警
     ↓
2. Heartbeat 轮询 getRealTimeAlarms() 获取
     ↓
3. AlarmQueue.push() 入队（P3 → 快速通道，P2/P1/P0 → 主队列）
     ↓
4. processAlarm() 消费
     ├─ 并行采集：getHomePage() + getBmsYx() + getPcsYc() + getPcsYx()
     ├─ 并行采集：getHistoryAlarms()
     ├─ checkThresholds() 阈值检查
     ├─ insertRealtimeSnapshot() 存快照
     └─ AgentLoop.run() 进入推理循环
          ├─ LLMClient.call() 第 1 轮
          │    └─ 返回 tool_use（如 getPcsYx）
          ├─ ToolRouter.execute() 执行工具
          │    └─ axios.get(EMS_BASE_URL + '/api/pcs/yx')
          ├─ LLMClient.call() 第 2 轮（带工具结果）
          │    └─ 返回 tool_use（如 getMeterYc）
          ├─ ... 循环最多 20 次或达到 token 上限
          └─ 最终返回 text 结论
     ↓
5. notifyOperator() 发送邮件 + 钉钉
     ↓
6. updateAlarmFinished() 更新数据库状态
```

## §6 扩展指引

### 沉淀模式

1. **Repository 模式**: db/ 目录下每个 Repository 封装一张表的 CRUD，避免 SQL 散落各处
2. **工具定义与实现分离**: tools/index.ts 定义 TOOLS_DEFINITION（LLM 可见），tools/queryEms.ts 实现具体逻辑
3. **热加载配置**: KNOWLEDGE.md 和 self-improvement.md 每次推理时重新读取，无需重启
4. **E2 Token 熔断**: AgentLoop 累计 input+output token，超过 LLM_MAX_TOKENS_PER_ALARM（默认 200000）立即降级返回

### 项目特有约定

1. **告警优先级语义翻转**: P3 最严重（与业界 P0 最高相反），见 KNOWLEDGE.md
2. **P3 快速通道**: 200ms 轮询，不阻塞主队列，并发执行
3. **P0 告警跳过 LLM**: 低优先级提示类告警直接记录，节省 API 费用
4. **硬件故障单次调用**: runOnce() 不进循环，直接生成报告
5. **软件故障多轮推理**: run() 循环调用 LLM + 工具，最多 20 次迭代
6. **Shadow Mode**: E4 实验特性，并行跑候选 prompt，结果存 llm_calls.shadow_group='shadow'

### 依赖怪癖

1. **better-sqlite3**: 需要 Node 原生模块编译，Windows 需要 Visual Studio Build Tools
2. **tsx**: TypeScript 执行器，支持 ESM + .js 扩展名导入
3. **@anthropic-ai/sdk**: 0.80.0 版本，支持 prompt caching
4. **openai**: 4.98.0 版本，用于 OpenAI 兼容 Provider
5. **TypeScript 6.0.2**: 较新版本，需要 Node.js >= 18
